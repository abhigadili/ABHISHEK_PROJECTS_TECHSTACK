# 6. Dynamic routes

> **Version:** Next.js 16.4.5 · React 19.3.0 · TypeScript 5.9 (App Router, `cacheComponents` enabled). Examples use the App Router only (no Pages Router APIs). Deprecated or removed APIs are called out where relevant.

## 1. Concept explanation
A folder name in square brackets captures a URL segment as a parameter: `employees/[id]` matches `/employees/1`, `/employees/42`.

## 2. Syntax
```tsx
// app/employees/[id]/page.tsx
export default async function Page({ params }: PageProps<'/employees/[id]'>) {
  const { id } = await params;          // params is a Promise in Next 15+/16
  …
}
export function generateStaticParams() { return [{ id: '1' }]; }   // optional pre-generation
```

## 3. How Next.js implements it
In this version `params` and `searchParams` are **Promises** and reading them is a *runtime* access: under Cache Components it must happen inside `<Suspense>` (unless every value is pre-generated). `generateStaticParams` pre-renders known values at build time. `PageProps<'/employees/[id]'>` is generated by `next typegen`.

## 4. Actual EMS implementation
* `/employees/[id]` – layout (`[id]/layout.tsx`) awaits `params` inside a `<Header>` under `<Suspense>`, validates the id (`Number(id)`; non-integers → 404), and calls `loadEmployee(id)` which maps backend 404 → `notFound()` and 401/403 → `/unauthorized`.
* `/departments/[id]`, `/leaves/[id]`, `/attendance/[id]` – same pattern; each page validates `/^\d+$/` **before** calling the API (no wasted request, no injection into the API path).
* Child segments reuse the parent’s loader through request memoisation (`React.cache`) so the layout and the page do not fetch twice.

## 5. Relevant file paths
- `src/app/(dashboard)/employees/[id]/layout.tsx`
- `src/app/(dashboard)/employees/[id]/page.tsx`
- `src/lib/server/employee-access.ts`
- `src/app/(dashboard)/departments/[id]/page.tsx`
- `src/app/(dashboard)/leaves/[id]/page.tsx`
- `src/app/(dashboard)/attendance/[id]/page.tsx`

## 6. Practical use case
Opening `/employees/999999` shows the employee-specific not-found UI (not a crash) and `/employees/abc` is rejected without calling Express. Directly navigating to `/employees/42` works the same as clicking from the list.

## 7. Why the concept is used
Dynamic segments let one component render any record, and are the foundation for deep-linkable detail pages.

## 8. Advantages
- Deep links and shareable URLs.
- Type-safe params.
- Validation at the edge of the route.

## 9. Limitations
- `params` are strings — always validate/convert.
- Dynamic routes of private data cannot be statically generated.

## 10. Common mistakes
- Forgetting `await params` (it is a Promise now).
- Trusting `params.id` as a number.
- Fetching the same record in the layout and the page without memoisation.

## 11. Interview-related considerations
- What does `generateStaticParams` do?
- Why are `params` async now (streaming/PPR)?
