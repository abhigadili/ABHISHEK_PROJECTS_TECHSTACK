# Routing and Rendering

Exact locations are relative to `src/app` unless a full `src/…` path is given (module paths such as `patients/…`, `appointments/…` live inside the `(dashboard)` route group folder). Build output of `next build` (Next.js 16.4.6, Turbopack) classifies every route: **○ static, ● SSG (`generateStaticParams`), ƒ dynamic**, plus the `Proxy`.

## App Router
File-system routing; typed route helpers (`PageProps<'/patients/[patientId]'>`, `LayoutProps<>`, `RouteContext<>`) are generated by `next typegen`/`next build`. `params` and `searchParams` are **Promises** in this version (`await params`).

## Dynamic routes
| Route | File | Notes |
|---|---|---|
| `/patients/[patientId]` (+ `/edit`, `/medical-records`, `/appointments`, `/prescriptions`, `/lab`, `/billing`) | `(dashboard)/patients/[patientId]/**` | `parseId()` rejects non-numeric ids with `notFound()` |
| `/doctors/[doctorId]` (+ `/schedule`, `/availability`, `/appointments`, `/edit`) | `(dashboard)/doctors/[doctorId]/**` | |
| `/appointments/[appointmentId]` (+ `/reschedule`) | `(dashboard)/appointments/[appointmentId]/**` | also rendered as a modal (intercepting route) |
| `/hospitals/[hospitalId]`, `/laboratory/[requestId]`, `/prescriptions/[prescriptionId]`, `/billing/invoices/[invoiceId]`, `/pharmacy/orders/[orderId]`, `/pharmacy/medicines/[medicineId]`, `/notifications/[notificationId]`, `/medical-records/[entryId]` | `(dashboard)/<module>/[id]/page.tsx` | |
| Multiple segments | `/billing/invoices/[invoiceId]`, `/patients/[patientId]/medical-records` | a nested static segment under a dynamic one |
| Catch-all `[...topic]` | `(public)/public/help/[...topic]/page.tsx` | `/public/help/appointments/booking` |
| Optional catch-all `[[...slug]]` | `(public)/public/info/[[...slug]]/page.tsx` | `/public/info`, `/public/info/emergency/contacts` |

## Nested routes and layouts
`app/layout.tsx` → `(dashboard)/layout.tsx` (authenticated shell, server-side session validation) → `patients/layout.tsx` (MUI provider) → `patients/[patientId]/layout.tsx` (patient header + tab bar, loads the patient once) → page. Doctors have the same pattern (`doctors/layout.tsx` → `doctors/[doctorId]/layout.tsx`). `(dashboard)/dashboard/layout.tsx` composes parallel slots.

## Route groups
`(public)` (marketing + catalogue layout), `(auth)` (centred card layout), `(dashboard)` (app shell), `(dashboard)/(admin)` (server-side `users:manage` gate for `/admin/**`). The group names never appear in URLs. **Private folders** (`_folder`) were not needed because shared code lives outside `app/` (`features/`, `components/`, `lib/`).

## Parallel routes
| Where | Slots | Files |
|---|---|---|
| `/dashboard` | `@stats`, `@upcoming`, `@activity` | `(dashboard)/dashboard/layout.tsx`, `…/@stats/page.tsx` + `loading.tsx` + `default.tsx`, same for the other two |
| `/appointments` | `@modal` | `(dashboard)/appointments/layout.tsx`, `…/@modal/default.tsx` |

Each dashboard slot has its own `loading.tsx`, so figures, upcoming appointments and activity stream independently.

## Intercepting routes + modal routing
`(dashboard)/appointments/@modal/(.)[appointmentId]/page.tsx` intercepts `/appointments/[appointmentId]` when navigating from `/appointments` (soft navigation) and renders `features/appointments/RouteModal.tsx` (Radix dialog) *over* the list. A hard load or a shared link renders the full page `(dashboard)/appointments/[appointmentId]/page.tsx`. Closing the modal calls `router.back()`. **Verified live**: click → URL changes + dialog visible + list still rendered; Esc → back to `/appointments`.

## Templates, loading, error, global error, not-found
`(dashboard)/template.tsx` (re-mounts per navigation), `loading.tsx` (root, dashboard group, slots, medical records), `error.tsx` (root, dashboard group, medical records), `global-error.tsx`, `not-found.tsx` (root + dashboard). Control flow: `notFound()` (`lib/api/guards.ts`), `redirect()` (`patients/me`, auth actions, admin index), `permanentRedirect()` (`(public)/public/page.tsx`).

## Route Handlers
Inventory (`app/api/**/route.ts`): `backend/[...path]` (GET/POST/PUT/PATCH/DELETE pass-through), `appointments/[appointmentId]` (GET/PATCH/PUT/DELETE), `lab/requests/[requestId]/attachment` (GET download, POST upload), `prescriptions/[prescriptionId]/download` (GET), `patients/export` (GET CSV stream), `dashboard/summary` (GET), `dashboard/activity` (GET NDJSON stream), `preferences` (GET/POST/DELETE), `auth/session` (GET), `auth/logout` (POST), `revalidate` (POST), `health` (GET). Details: [`SERVER_ACTIONS_AND_BACKEND.md`](SERVER_ACTIONS_AND_BACKEND.md).

## Server and Client Components
Server by default; client islands listed in [`NEXTJS_ARCHITECTURE.md`](NEXTJS_ARCHITECTURE.md#client-components). `DashboardShell` (client) renders server children; `RecordsTabs` (client) renders three server panels.

## Rendering decisions

| Strategy | What it is | Where (exact page) | Why this strategy |
|---|---|---|---|
| **SSG** | HTML built at `next build` | `page.tsx` (landing), `(public)/public/info/[[...slug]]`, `(public)/public/help/[...topic]`, `(auth)/register`, `unauthorized` | Content never depends on the user or on changing data |
| **SSG + `generateStaticParams`** | one page per known param | `(public)/public/hospitals/[hospitalId]`, `(public)/public/doctors/[doctorId]` (first 30) | Public facts; unknown ids render on first request (`dynamicParams`) |
| **ISR (time)** | static + background regeneration | `/public/hospitals` (`revalidate = 3600`), `/public/doctors` (`300`), `sitemap.ts` (`3600`) | Directory changes rarely but must not go stale |
| **ISR (on-demand)** | `revalidateTag/Path` | `actions/doctors.ts`, `actions/hospitals.ts`, `api/revalidate/route.ts` | Edits must show immediately. **Verified**: editing a doctor's fee / adding a department changed the public page on the next visit |
| **SSR / Dynamic** | HTML per request | `/dashboard`, `/patients/**`, `/appointments/**`, `/billing/**`, `/laboratory/**`, `/medical-records/**`, `/prescriptions/**`, `/pharmacy/**`, `/notifications/**` | Personal/sensitive data needs the caller's identity and must never be shared-cached |
| **CSR** | browser renders and fetches | `features/doctors/DoctorsBoard.tsx` (Redux), `features/laboratory/LabRequestsInfinite.tsx`, `features/pharmacy/MedicineBrowser.tsx`, `features/appointments/BookingWizard.tsx`, `features/public/DoctorDirectory.tsx` (filter) | Rapid interaction (search/filter/sort/booking) without server round trips per keystroke |
| **Streaming** | send shell first | `/dashboard` slots; `/patients/[id]/medical-records` panels; `api/dashboard/activity` (NDJSON) | Slow services (appointments aggregation, billing) must not block the page |
| **Suspense** | boundaries with fallbacks | `medical-records/page.tsx`, `laboratory/[requestId]/page.tsx` (`Report`), `laboratory/tests/page.tsx` (`use()`), `appointments/book/page.tsx` | Independent panels, and `useSearchParams` requires one |
| **Dynamic rendering** | opts out of static | any page reading `cookies()`/`searchParams` | Per-request data |
| **Static rendering** | opts in | public pages | See SSG |

Notes: `@defer` is not a Next.js feature — Suspense, parallel-route slots and `useDeferredValue` (directory search) provide deferred UI. Hydration is selective: each Suspense boundary and client island hydrates independently; `ThemeProvider` uses `useSyncExternalStore` so server/client markup always match.
