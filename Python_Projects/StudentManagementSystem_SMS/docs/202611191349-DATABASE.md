# Database

MySQL 8, SQLAlchemy 2.x ORM, Alembic migrations. **Five databases, one per service** — created fresh for this project; no existing database is used, altered or dropped.

## 1. Creating the databases

### Local run (host MySQL)

```bash
source .venv/bin/activate
python scripts/init_databases.py
```

`scripts/init_databases.py` connects with `MYSQL_USER` / `MYSQL_PASSWORD` from `.env` and runs, for each name, `CREATE DATABASE IF NOT EXISTS … CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci`. It is idempotent and never drops anything. Output on a fresh server:

```
created  StudentManagementAuthDB
created  StudentManagementStudentDB
created  StudentManagementCourseDB
created  StudentManagementEnrollmentDB
created  StudentManagementNotificationDB
```

The MySQL account needs `CREATE` plus DDL/DML rights on `StudentManagement%`. Credentials live **only** in `.env` (gitignored) or the environment — never in source.

### Docker Compose

`docker/mysql/10-init-databases.sh` runs once on the first start of an empty `mysql-data` volume, creates the same five databases and grants the application user `ALL` on ``StudentManagement%.*`` only.

### Tables

Tables are created by **Alembic**, not by `create_all()`. Each service applies its own migration at container start (`docker/entrypoint.sh`: `alembic upgrade head`) or manually (§5).

## 2. Connection management, sessions, transactions

| Concern | Implementation (`libs/sms_common/src/sms_common/db.py`) |
|---|---|
| URL building | `BaseServiceSettings.async_database_url()` / `sync_database_url()` use `sqlalchemy.engine.URL.create`, which escapes special characters in the password (e.g. `@`, `:`, `/`). |
| Drivers | async: `mysql+aiomysql`; sync + Alembic: `mysql+pymysql`; `charset=utf8mb4`. |
| Pooling | `pool_size=10`, `max_overflow=10`, `pool_recycle=1800`, `pool_pre_ping=True` (env-tunable: `DB_POOL_SIZE`, …). |
| Time zone | every pooled connection runs `SET time_zone='+00:00'`; the application stores **naive UTC** datetimes, and server defaults (`NOW()`) agree with it whatever the server's zone. |
| Async sessions | `Database.session_dependency` → `async_sessionmaker(expire_on_commit=False)`; used by Student, Course, Enrollment, Notification and by all background jobs (`Database.async_session()` context manager). |
| Sync sessions | `Database.sync_session_dependency` → `sessionmaker`; used by **every Auth endpoint** (they are plain `def` → threadpool) and by `GET /students/stats`. |
| Transactions | **The service layer owns the transaction.** Repositories only `add/flush/execute`; the service calls `commit()` once per business operation so the domain change **and** its outbox row commit together. The session dependency guarantees `rollback()` on any exception and closes the session. |
| Commit/rollback examples | Auth `authenticate()` commits the failed-login counter *before* raising 401; `StudentFileService.upload_picture` rolls back and deletes the orphan file when the DB write fails. |
| Advisory locks | `named_lock(engine, name)` — `GET_LOCK/RELEASE_LOCK` on a dedicated connection (enrollment capacity). |
| Health | `Database.ping()` (`SELECT 1`) feeds `/health/ready`. |

## 3. Relationships (what each ORM mapping demonstrates)

```
AUTH                                   STUDENT
 users ─┬─< refresh_tokens   (1:N)       departments ─< students ─┬─ student_profiles   (1:1, PK = FK)
        ├─< password_reset_tokens (1:N)                           ├─< contact_infos     (1:N)
        └─<user_roles>─ roles  (N:M,                              ├─< student_files     (1:N)
           composite PK)                                          └─<student_interests>─ interests (N:M, composite PK)

COURSE                                 ENROLLMENT                          NOTIFICATION
 categories ─< courses ─┬─< course_files (1:N)        enrollments ─< enrollment_status_history (1:N)      notifications ─< notification_attempts (1:N)
                        └─< course_teachers (association object, composite PK course_id+teacher_user_id)
```

| Concept | Where | Notes |
|---|---|---|
| Declarative base + naming convention | `sms_common/db.py::Base` | deterministic constraint names (`fk_…`, `uq_…`, `ix_…`) make Alembic diffs stable |
| Mixins | `TimestampMixin`, `StoredFileMixin`, `OutboxEventMixin`, `ProcessedEventMixin` | shared columns without inheritance of tables |
| Primary keys | all tables | surrogate `id` (auto-increment) |
| **Composite keys** | `user_roles`, `student_interests`, `course_teachers`, `processed_events (event_id, consumer_group)` | |
| Foreign keys + `ON DELETE` | e.g. `student_profiles.student_id … CASCADE`, `students.department_id … RESTRICT` | FKs exist **only inside one database** |
| Unique constraints | `users.email`, `students.email`, `courses.code`, `uq_enrollment_student_course (student_id, course_id)`, `uq_contact_student_type_value`, `notifications.event_id`, … | the enrollment unique constraint is the database-level guard behind "no duplicate enrollments" |
| Check constraints | `students.gpa_range`, `courses.credits_range / capacity_range / dates_ordered` | |
| Indexes | `ix_students_department_status`, `ix_students_name`, `ix_courses_category_status`, `ix_enrollments_course_status`, `ix_outbox_events_status_id`, `ix_notifications_due (status, next_attempt_at)` … | each matches a real query/filter |
| **One-to-one** | `Student.profile` ↔ `StudentProfile.student` (`uselist=False`, `cascade="all, delete-orphan"`, PK = FK) | `StudentService._merge_profile` |
| **One-to-many** | `Department.students`, `Student.contacts`, `User.refresh_tokens`, `Enrollment.history` | `back_populates` on both sides |
| **Many-to-many** | `User.roles` (`secondary=user_roles`), `Student.interests` (`secondary=student_interests`) | `InterestRepository.get_or_create` loads existing rows with one `IN` query |
| **Association object** | `Course.teachers` → `CourseTeacher` (extra columns: role, name/e-mail snapshot, `assigned_at`) | `CourseRepository.teacher()` uses a composite-key `session.get(CourseTeacher, (course_id, user_id))` |
| Cascades | `delete-orphan` on profile/contacts/history/attempts; `passive_deletes=True` + DB `ON DELETE CASCADE` for big collections | deleting a student removes profile, contacts, files, interests links in the DB |

### Loading strategies (avoiding N+1)

| Strategy | Used for | Code |
|---|---|---|
| **Lazy** (`lazy="select"`, default) | rarely-needed collections (`Department.students`, `Student.files`) | never touched in async code paths |
| **Joined** (`joinedload`) | to-one relations on lists/details: `Student.department`, `Student.profile`, `Course.category` | `student/app/repositories.py::DETAIL_OPTIONS / LIST_OPTIONS` |
| **Select-in** (`selectinload`) | collections: `Student.contacts`, `Student.interests`, `Course.teachers`, `Enrollment.history`, `Notification.attempt_log` | one extra `WHERE id IN (…)` query, no row multiplication |
| `lazy="selectin"` on the mapping | `User.roles` (needed on nearly every Auth request) | `auth/app/models.py` |
| `populate_existing` | re-reading after commit so collections are fresh | `StudentRepository.get`, `CourseRepository.get`, `EnrollmentRepository.reload` |

Result: the student detail view costs **3 queries** regardless of how many contacts/interests exist; a student list page costs **2** (count + page with the department joined).

> **Async gotcha, solved explicitly:** an async session cannot lazy-load. Any attribute not loaded raises `MissingGreenlet`. Two real bugs of exactly this kind were found by the live tests (server-default `created_at` after INSERT, and `e.history.append()` on an unloaded collection) — see *Troubleshooting* in SETUP_AND_EXECUTION.md. The rules now followed: explicit eager loading, `session.refresh()`/re-read after commit, explicit `INSERT` instead of touching an unloaded relationship.

### Query techniques (all in `*/app/repositories.py` or API handlers)

| Technique | Example |
|---|---|
| Filtering (dynamic `WHERE`) | `StudentRepository.filtered()` — name/e-mail LIKE, department join, status, gender, admission year (`EXTRACT`), GPA range, has-enrollments |
| Search + OR | `Student.first_name.like(..) \| last_name \| email \| student_number \| CONCAT(first,' ',last)` |
| Whitelisted sorting + stable tiebreak | `sms_common/pagination.py::apply_sort` — never interpolates user input into SQL |
| Pagination | `count_for()` (count over a subquery) + `LIMIT/OFFSET` |
| Aggregation + `GROUP BY` | `/students/stats` (by status, by department with `AVG(gpa)`), `/enrollments/stats` |
| Outer join | departments with zero students still listed; roles with user counts (`RoleRepository.list_with_user_counts`) |
| **Subqueries** | correlated scalar subquery — students whose GPA beats **their department's average** (`/students/stats`); subquery in `FROM` — students with more than one active enrollment (`students_with_multiple_active`); correlated `EXISTS` for "courses taught by teacher X" |
| Conditional aggregation | `SUM(CASE WHEN status=… )` per course (`EnrollmentRepository.per_course`) |
| **Bulk operations** | `UPDATE … WHERE id IN (…)` (`bulk_set_status`), `add_all` of up to 500 students in one transaction (`bulk_import`), bulk revoke of refresh tokens (`revoke_all_for_user`), bulk snapshot refresh (`refresh_*_snapshot`) |
| Row locking | `with_for_update()` on refresh tokens / reset tokens; `FOR UPDATE SKIP LOCKED` on the outbox and the notification queue |
| Atomic counters | `SET enrolled_count = GREATEST(enrolled_count + :d, 0)` — no read-modify-write race |

## 5. Migrations (Alembic)

Layout per service: `services/<svc>/alembic.ini`, `alembic/env.py`, `alembic/versions/0001_*.py`. `env.py` builds the URL from the service's own `Settings` (no password in `alembic.ini`) and enables `compare_type` / `compare_server_default`.

```bash
cd services/student
alembic upgrade head                 # apply
alembic current                      # which revision is applied
alembic check                        # "No new upgrade operations detected." == models match the DB
alembic history
alembic downgrade base               # roll back (drops this service's tables only)
```

### Creating a new revision

```bash
cd services/student
# (1) after changing models.py – diff against the real database:
alembic revision --autogenerate -m "add student nickname"
# (2) strip MySQL-hostile drop_index calls from downgrade():
python ../../scripts/fix_downgrade.py alembic/versions/<new file>.py
# (3) review the file, then:
alembic upgrade head && alembic check
```

For the very first revision the baseline was autogenerated against a throw-away SQLite file with Alembic's `-x` argument (`alembic -x dburl=sqlite:///scratch.db revision --autogenerate …`; `env.py` honours `-x dburl`), so no MySQL schema had to be touched.

**Why `fix_downgrade.py`:** autogenerate emits `op.drop_index()` before `op.drop_table()`. MySQL refuses to drop an index that a foreign key still needs (error 1553) — a downgrade failed half-way through during development. Dropping the table drops its indexes, so the explicit calls are removed.

### Verified

* `alembic upgrade head` ran on all five databases (host MySQL) and again on the containerised MySQL by the container entrypoint.
* `alembic check` reports no drift for all five services.
* Table counts (incl. `alembic_version`): Auth 7, Student 10, Course 7, Enrollment 5, Notification 4 — identical locally and in Docker.
