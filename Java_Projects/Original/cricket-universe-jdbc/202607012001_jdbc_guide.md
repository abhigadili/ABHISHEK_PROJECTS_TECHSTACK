## What is JDBC?

**JDBC (Java Database Connectivity)** is the standard Java API for connecting Java applications to relational databases. It lets you:
- Open a connection to a database
- Send SQL queries and updates
- Read results back as Java objects
- Call stored procedures and functions

JDBC is **vendor-neutral** — the same Java code works with MySQL, PostgreSQL, Oracle, etc. by swapping the driver JAR.

## Step 1 — MySQL Driver Dependency (pom.xml)

Maven downloads the MySQL JDBC driver automatically:

```xml
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <version>8.3.0</version>
</dependency>
```

The driver class `com.mysql.cj.jdbc.Driver` is loaded automatically by Java's `ServiceLoader` mechanism — no `Class.forName()` call needed in JDBC 4.0+.

## Step 2 — Database Connection (DBConnection.java)

### Connection URL

```java
String URL = "jdbc:mysql://localhost:3306/cricket_universe"
           + "?useSSL=false"
           + "&serverTimezone=UTC"
           + "&characterEncoding=UTF-8"
           + "&connectionCollation=utf8mb4_unicode_ci"  // match table collation
           + "&allowPublicKeyRetrieval=true";
```

**Key URL parameters explained:**

| Parameter | Why |
|-----------|-----|
| `useSSL=false` | Disables SSL for local development |
| `serverTimezone=UTC` | Prevents timezone ambiguity errors |
| `characterEncoding=UTF-8` | Handles emoji and unicode characters |
| `connectionCollation=utf8mb4_unicode_ci` | Matches the table collation — prevents collation mismatch error 1267 |
| `allowPublicKeyRetrieval=true` | Required when not using SSL |

### Singleton Pattern

```java
public static Connection getConnection() throws SQLException {
    if (connection == null || connection.isClosed()) {
        connection = DriverManager.getConnection(URL, USER, PASSWORD);
    }
    return connection;
}
```

A singleton connection is fine for a single-threaded demo. In production apps, use a **connection pool** (HikariCP, c3p0) to handle concurrent requests.

## Step 3 — Model Classes (POJOs)

A **POJO (Plain Old Java Object)** represents one row of a database table. Example:

```java
public class Country {
    private String id;
    private String name;
    private String shortName;
    private int worldCupsWon;
    // ... getters and setters
}
```

POJOs decouple your Java code from JDBC — the DAO maps ResultSet columns to POJO fields, and the rest of your code works with typed Java objects.

## Step 4 — DAO Pattern (Data Access Object)

A **DAO** centralises all database operations for one entity. The three JDBC statement types used:

### Statement — simple queries with no parameters

```java
Statement st = con.createStatement();
ResultSet rs = st.executeQuery("SELECT * FROM countries ORDER BY name");
```

Use `Statement` only when the SQL has **no user-provided values** (to avoid SQL injection).

### PreparedStatement — parameterised queries (safe)

```java
PreparedStatement ps = con.prepareStatement(
    "SELECT * FROM countries WHERE id = ?"
);
ps.setString(1, "ind");   // ? placeholder replaced safely
ResultSet rs = ps.executeQuery();
```

**Always use `PreparedStatement` with user input.** The `?` is a bind parameter — the driver sends it separately from the SQL, preventing SQL injection.

### CallableStatement — stored procedures and functions

```java
CallableStatement cs = con.prepareCall("{CALL sp_list_countries(?)}");
cs.setString(1, "india");
ResultSet rs = cs.executeQuery();
```

## Step 5 — Reading ResultSet

```java
while (rs.next()) {                        // move cursor to next row
    String id   = rs.getString("id");      // get column by name
    int    cups = rs.getInt("world_cups_won");
    country.setId(id);
    country.setWorldCupsWon(cups);
}
```

**Always iterate with `while (rs.next())`** — the cursor starts BEFORE the first row.

### Try-with-resources (auto-close)

```java
try (Connection con = DBConnection.getConnection();
     PreparedStatement ps = con.prepareStatement(sql);
     ResultSet rs = ps.executeQuery()) {
    while (rs.next()) { ... }
}   // connection, ps, rs all auto-closed here
```

This prevents resource leaks — even if an exception is thrown, the resources are closed.

## Step 7 — Calling Stored Procedures

```java
// Call sp_list_leagues with two parameters
CallableStatement cs = con.prepareCall("{CALL sp_list_leagues(?, ?)}");
cs.setString(1, "ind");    // p_country_id
cs.setString(2, "");       // p_search (empty = no filter)

boolean hasResultSet = cs.execute();
if (hasResultSet) {
    ResultSet rs = cs.getResultSet();
    while (rs.next()) {
        System.out.println(rs.getString("name"));
    }
}
```

**Stored procedures called:**

## Step 8 — Calling MySQL User-Defined Functions

MySQL functions are called **inline in SQL**, not via `{CALL ...}`:

```java
// fn_batting_average used inside a SELECT
String sql = "SELECT cr.name, cr.runs, cr.matches, " +
             "fn_batting_average(cr.runs, cr.matches) AS batting_avg " +
             "FROM cricketers cr WHERE cr.matches > 0 ORDER BY batting_avg DESC";

ResultSet rs = st.executeQuery(sql);
while (rs.next()) {
    double avg = rs.getDouble("batting_avg");
}
```

**Functions created for this application:**

| Function | Parameters | Returns | Description |
|----------|-----------|---------|-------------|
| `fn_batting_average` | runs INT, matches INT | DECIMAL(10,2) | Runs ÷ matches |
| `fn_player_grade` | runs INT, wickets INT, role VARCHAR | VARCHAR(20) | Legendary/Elite/Excellent/Good/Developing |
| `fn_format_player_label` | name, role, team VARCHAR | VARCHAR(300) | "Name [Role] — Team" display string |

## Step 9 — Audit Tables & Triggers Demonstration

The application proves triggers fire automatically:

```java
// 1. INSERT — trg_cricketers_after_insert fires → writes to audit_cricketers
ps = con.prepareStatement("INSERT INTO cricketers (id, team_id, name, role, ...) VALUES (?,?,?,?,...)");
ps.executeUpdate();

// 2. UPDATE — trg_cricketers_after_update fires → writes old + new values
ps = con.prepareStatement("UPDATE cricketers SET runs = 500 WHERE id = ?");
ps.executeUpdate();

// 3. DELETE — trg_cricketers_after_delete fires → writes old values
ps = con.prepareStatement("DELETE FROM cricketers WHERE id = ?");
ps.executeUpdate();

// 4. Read the auto-generated audit rows
ps = con.prepareStatement("SELECT * FROM audit_cricketers WHERE record_id = ?");
ResultSet rs = ps.executeQuery();
```

## Common Beginner Mistakes & Fixes

| Mistake | Fix |
|---------|-----|
| `Class.forName("com.mysql.jdbc.Driver")` | Not needed in JDBC 4.0+ — driver auto-registers |
| `Statement` with user input | Always use `PreparedStatement` with `?` parameters |
| Not closing ResultSet/Statement | Use try-with-resources |
| Hardcoding credentials | Use environment variables or a `.properties` file |
| Single Connection for multi-threading | Use a connection pool (HikariCP) |
| Collation mismatch error 1267 | Add `&connectionCollation=utf8mb4_unicode_ci` to the JDBC URL |
| `{CALL sp_name()}` for functions | Functions go inline in SQL: `SELECT fn_name(...)` |
