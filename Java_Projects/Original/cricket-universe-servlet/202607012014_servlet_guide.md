## 1. What Are Servlets? {#what-are-servlets}

A **servlet** is a Java class that handles HTTP requests. You write one class per resource (countries, leagues, teams…) and override methods named after HTTP verbs:

```
doGet()     → handles GET requests
doPost()    → handles POST requests
doPut()     → handles PUT requests
doDelete()  → handles DELETE requests
doOptions() → handles CORS preflight
```

The servlet container (Tomcat in our case) receives incoming TCP connections, parses the HTTP protocol, and calls the right method for you. Your code only deals with `HttpServletRequest` and `HttpServletResponse` objects — no socket programming required.

**Jakarta EE 9** renamed the package from `javax.servlet.*` to `jakarta.servlet.*`. Tomcat 10 uses the new name, so every import in this project starts with `jakarta.servlet`.

## 4. Dependencies Explained {#dependencies-explained}

```xml
<!-- pom.xml -->
<dependencies>
    <!-- MySQL JDBC driver: translates Java calls into MySQL wire protocol -->
    <dependency>
        <groupId>com.mysql</groupId>
        <artifactId>mysql-connector-j</artifactId>
        <version>8.3.0</version>
    </dependency>

    <!-- Embedded Tomcat: the HTTP server lives inside our JAR -->
    <dependency>
        <groupId>org.apache.tomcat.embed</groupId>
        <artifactId>tomcat-embed-core</artifactId>
        <version>10.1.20</version>
    </dependency>

    <!-- Gson: converts Java objects ↔ JSON strings -->
    <dependency>
        <groupId>com.google.code.gson</groupId>
        <artifactId>gson</artifactId>
        <version>2.10.1</version>
    </dependency>
</dependencies>
```

**Why `maven-shade-plugin` (not `maven-assembly-plugin`)?**

Tomcat registers its internal components using Java's SPI (Service Provider Interface) mechanism — it reads files from `META-INF/services/` inside JARs. When building a fat JAR, both plugins bundle all dependencies together. However:

- `maven-assembly-plugin` silently **overwrites** duplicate `META-INF/services` files, so only one provider survives → Tomcat fails to start.
- `maven-shade-plugin` with `ServicesResourceTransformer` **merges** all service files → Tomcat starts correctly.

This is why the build section uses shade:

```xml
<transformer implementation=
    "org.apache.maven.plugins.shade.resource.ServicesResourceTransformer"/>
```

## 5. How the Layers Fit Together {#how-the-layers-fit-together}

Trace a `GET /api/countries?search=india` request through every layer:

```
1. Browser → TCP connection to port 8080
2. Tomcat parses HTTP: method=GET, path=/api/countries, query=search=india
3. URL pattern /api/countries/* matches → Tomcat calls CountryServlet.doGet()
4. CountryServlet.doGet():
       id = extractId(req)      // returns null (collection, not single resource)
       search = req.getParameter("search")  // "india"
       list = dao.findAll("india")
5. CountryDAO.findAll("india"):
       sql = "SELECT ... FROM countries WHERE name LIKE ? OR short_name LIKE ? OR board LIKE ?"
       ps.setString(1, "%india%")    // ? ← safe parameterised binding
       ps.setString(2, "%india%")
       ps.setString(3, "%india%")
       rs = ps.executeQuery()
       maps each row to a Country object
       returns List<Country>
6. CountryServlet calls sendList(res, list, list.size())
7. BaseServlet.sendList():
       adds CORS headers
       sets Content-Type: application/json
       writes GSON.toJson(body)  → {"success":true,"data":[...],"total":1}
8. Tomcat sends HTTP response back to browser
```

## 6. SQL Injection Prevention — The Complete Picture {#sql-injection-prevention}

### What is SQL Injection?

SQL injection is an attack where a user crafts input that changes the meaning of your SQL query. Classic example:

```java
// VULNERABLE — never do this:
String sql = "SELECT * FROM countries WHERE name = '" + userInput + "'";
```

If `userInput` is `' OR '1'='1`, the query becomes:
```sql
SELECT * FROM countries WHERE name = '' OR '1'='1'
```
This returns every row. Worse payloads can drop tables, read other databases, or bypass authentication.

### The Fix: Prepared Statements with `?` Placeholders

Every DAO method in this project uses `PreparedStatement`:

```java
// SAFE — every DAO in this project works this way:
String sql = "SELECT * FROM countries WHERE name LIKE ?";
try (PreparedStatement ps = con.prepareStatement(sql)) {
    ps.setString(1, "%" + userInput + "%");   // ← bound as data, never as SQL
    ResultSet rs = ps.executeQuery();
    ...
}
```

**Why this works:**

The JDBC driver sends the SQL template and the parameter value **separately** over the wire to MySQL:

```
Step 1 — MySQL receives:  SELECT * FROM countries WHERE name LIKE ?
Step 2 — MySQL receives:  parameter[1] = "%' OR '1'='1%"
```

MySQL treats the parameter as a plain string literal. It will search for a country whose name literally contains the text `' OR '1'='1` — which matches nothing — instead of altering the query structure. The attacker's SQL tokens are never interpreted as SQL.

### Dynamic Queries Without Injection

Some endpoints accept multiple optional filters. Naively you might do:

```java
// WRONG:
if (search != null) sql += " AND name LIKE '%" + search + "%'";
```

This project uses the **`WHERE 1=1` pattern** with a `List<Object>` for parameters:

```java
StringBuilder sb = new StringBuilder("SELECT ... FROM leagues WHERE 1=1");
List<Object> params = new ArrayList<>();

if (countryId != null) {
    sb.append(" AND l.country_id = ?");
    params.add(countryId);            // ← collected, not concatenated
}
if (search != null) {
    sb.append(" AND l.name LIKE ?");
    params.add("%" + search + "%");   // ← still just data
}

PreparedStatement ps = con.prepareStatement(sb.toString());
for (int i = 0; i < params.size(); i++) {
    ps.setObject(i + 1, params.get(i));  // ← bound safely at runtime
}
```

The SQL structure is built from **our own constant strings only** — user input is never concatenated. User data arrives only as values bound through `setObject()`.

### Three Layers of Defense

| Layer | Mechanism | Location |
|-------|-----------|----------|
| Primary | PreparedStatement + `?` everywhere | All DAO classes |
| Secondary | Typed parameter binding (`setString`, `setInt`) | All DAOs — wrong types throw before hitting DB |
| Tertiary | Input validation in servlets | Check required fields, parse `int` params safely |

### `ProcedureServlet` — Stored Procedures Are Also Safe

Stored procedures are called via `CallableStatement`:

```java
CallableStatement cs = con.prepareCall("{CALL sp_list_players(?,?)}");
cs.setString(1, teamId);    // ← parameter, not SQL
cs.setString(2, role);
cs.execute();
```

The procedure call itself uses `?` — the same parameterised binding. The stored procedure runs inside MySQL with its own compiled execution plan; user-supplied values cannot escape into SQL syntax.

### `ViewServlet` — Safe Dynamic Table Name

`ViewServlet` builds a query like `SELECT * FROM v_countries_leagues`. The view name is **never** from user input — it comes from a Java `switch` statement over the URL path:

```java
String viewName = switch (path) {
    case "/countries-leagues" -> "v_countries_leagues";   // our constant
    case "/teams-players"     -> "v_teams_players";       // our constant
    case "/all-players"       -> "v_all_players_detail";  // our constant
    default -> null;  // anything else → 404
};
// If viewName is null we return 404 before building any SQL
String sql = "SELECT * FROM " + viewName;  // safe: viewName is always one of 3 fixed strings
```

## 7. The DAO Layer {#the-dao-layer}

DAO stands for **Data Access Object**. Each DAO class owns all SQL for one table.

### `DBConnection.java` — Connection per Request

```java
public class DBConnection {
    private static final String URL =
        "jdbc:mysql://localhost:3306/cricket_universe" +
        "?useSSL=false&allowPublicKeyRetrieval=true" +
        "&connectionCollation=utf8mb4_unicode_ci";

    public static Connection getConnection() throws SQLException {
        return DriverManager.getConnection(URL, "root", "root");
    }
}
```

**Why `connectionCollation=utf8mb4_unicode_ci`?**

The `cricketers` table uses `utf8mb4_unicode_ci`. MySQL's server default is `utf8mb4_0900_ai_ci`. When a JDBC connection sends a VARCHAR parameter with the wrong collation, MySQL raises:
```
SQL Error [1267]: Illegal mix of collations
```
Setting `connectionCollation` on the URL makes every connection use the same collation as the tables — the mismatch disappears.

**Why one connection per DAO call (not a singleton)?**

Servlets handle multiple concurrent HTTP requests across multiple threads. A single shared `Connection` is not thread-safe. Opening a fresh connection per DAO call avoids all threading bugs. In production, swap `DriverManager.getConnection()` with a HikariCP connection pool — it reuses connections safely across threads.

### Pattern: `mapRow()` method

Every DAO has a private `mapRow(ResultSet rs)` method:

```java
private Country mapRow(ResultSet rs) throws SQLException {
    Country c = new Country();
    c.setId(rs.getString("id"));
    c.setName(rs.getString("name"));
    // ... one line per column
    return c;
}
```

This centralises the column-name → field mapping so `findAll()` and `findById()` both call it — no duplication.

## 8. The Servlet Layer {#the-servlet-layer}

### `BaseServlet.java` — Shared Code

All 7 concrete servlets extend `BaseServlet`. It provides:

| Method | Purpose |
|--------|---------|
| `addCorsHeaders(res)` | Adds `Access-Control-Allow-*` headers |
| `doOptions(req, res)` | Handles browser preflight — returns 204 |
| `sendList(res, data, total)` | Writes `{"success":true,"data":[...],"total":N}` |
| `sendSuccess(res, data)` | Writes `{"success":true,"data":{...}}` — HTTP 200 |
| `sendCreated(res, data)` | Same but HTTP 201 |
| `sendError(res, status, msg)` | Writes `{"success":false,"error":"..."}` |
| `sendNoContent(res)` | HTTP 204 — for DELETE |
| `extractId(req)` | Parses `/{id}` from path info; null for collection URLs |
| `parseBody(req, Class)` | Reads JSON body and deserialises to object via Gson |

### `CountryServlet.java` — Routing Inside a Servlet

Tomcat matches `/api/countries/*` to this servlet. Inside, `extractId()` determines whether this is a collection request or a single-resource request:

```java
@Override
protected void doGet(HttpServletRequest req, HttpServletResponse res) throws IOException {
    String id = extractId(req);  // null for /api/countries, "india" for /api/countries/india
    try {
        if (id == null) {
            String search = req.getParameter("search");
            List<Country> list = dao.findAll(search);
            sendList(res, list, list.size());
        } else {
            Country c = dao.findById(id);
            if (c == null) sendError(res, 404, "Country not found: " + id);
            else           sendSuccess(res, c);
        }
    } catch (SQLException e) {
        sendError(res, 500, "DB error: " + e.getMessage());
    }
}
```

The `@WebServlet(urlPatterns = "/api/countries/*")` annotation is read by embedded Tomcat when we call `Tomcat.addServlet()` — or in our `Main.java` we register the pattern explicitly.

## 9. Embedded Tomcat — No External Server Needed {#embedded-tomcat}

Traditional servlet development requires:
1. Install Tomcat separately
2. Build a `.war` file
3. Drop the WAR into Tomcat's `webapps/` folder
4. Restart Tomcat

Embedded Tomcat inverts this: **Tomcat is a library inside your JAR**. The server starts from `main()`:

```java
Tomcat tomcat = new Tomcat();
tomcat.setPort(8080);

// Connector must be added explicitly
Connector connector = new Connector();
connector.setPort(8080);
tomcat.getService().addConnector(connector);

// Create an application context (docBase is just a required placeholder)
Context ctx = tomcat.addContext("", new File(".").getAbsolutePath());

// Register each servlet with its URL pattern
Tomcat.addServlet(ctx, "CountryServlet", new CountryServlet());
ctx.addServletMappingDecoded("/api/countries/*", "CountryServlet");

tomcat.start();
tomcat.getServer().await();  // blocks until CTRL+C
```

The result is a **single executable JAR** (`java -jar cricket-universe-servlet.jar`) that contains both your application and the HTTP server. This is how modern Java microservices (Spring Boot, Quarkus) work internally.

## 10. CORS — Letting React Call the API {#cors}

Browsers enforce the **Same-Origin Policy**: a React app running on `http://localhost:3000` is not allowed to call an API on `http://localhost:8080` by default. CORS (Cross-Origin Resource Sharing) is the standard that lets servers grant that permission.

`BaseServlet.addCorsHeaders()` is called on every response:

```java
res.setHeader("Access-Control-Allow-Origin",  "*");
res.setHeader("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS");
res.setHeader("Access-Control-Allow-Headers", "Content-Type, Authorization");
```

Browsers also send an **OPTIONS preflight request** before PUT/POST/DELETE to check permissions. `BaseServlet.doOptions()` handles this:

```java
@Override
protected void doOptions(HttpServletRequest req, HttpServletResponse res) throws IOException {
    addCorsHeaders(res);
    res.setStatus(HttpServletResponse.SC_NO_CONTENT);  // 204 — no body needed
}
```

In production, replace `"*"` with `"http://your-react-app.com"` to restrict access to specific origins.

## 11. MySQL Views via API {#mysql-views-via-api}

MySQL views are pre-defined `SELECT` queries stored in the database. Querying a view looks exactly like querying a table:

```java
// ViewServlet.java
String sql = "SELECT * FROM v_all_players_detail";  // view, not a table
PreparedStatement ps = con.prepareStatement(sql);
ResultSet rs = ps.executeQuery();
```

The three views expose denormalised data that avoids repeated JOINs in the application:

| View | Joins | Returns |
|------|-------|---------|
| `v_countries_leagues` | countries + leagues | Country with all its leagues |
| `v_teams_players` | leagues + teams + cricketers | Team with player count |
| `v_all_players_detail` | all 4 tables | Full player profile with team, league, country |

**Endpoint:**
```
GET /api/views/all-players
GET /api/views/countries-leagues
GET /api/views/teams-players
```

## 12. Stored Procedures via CallableStatement {#stored-procedures}

Stored procedures are SQL programs stored inside MySQL. They can accept parameters and return one or more result sets.

**JDBC calls a stored procedure with `CallableStatement`:**

```java
// In ProcedureServlet.java
CallableStatement cs = con.prepareCall("{CALL sp_list_players(?,?)}");
cs.setString(1, teamId);   // IN p_team_id — still parameterised, still safe
cs.setString(2, role);     // IN p_role
boolean hasResultSet = cs.execute();
if (hasResultSet) {
    ResultSet rs = cs.getResultSet();
    // read rows...
}
```

The `{CALL ...}` syntax is a JDBC escape that Tomcat/MySQL driver translates to the correct database call format. The `?` placeholders work exactly the same as in regular PreparedStatement — values are bound as data, never as SQL.

**Note on NULL parameters:** Our stored procedures treat `NULL` as "no filter" and return all rows. We use `cs.setNull(i+1, Types.VARCHAR)` when the parameter is absent from the query string.

**Endpoints:**
```
GET /api/procedures/list-countries?search=india
GET /api/procedures/cursor-role-totals
GET /api/procedures/window-functions
GET /api/procedures/analytics
```

## 13. MySQL UDFs via Inline SQL {#mysql-udfs}

MySQL User-Defined Functions (UDFs) are called **inside a SELECT** statement, unlike stored procedures which use `CALL`. This means you call them through a regular `PreparedStatement`:

```java
// FunctionServlet.java
String sql = "SELECT fn_batting_average(?, ?) AS batting_average";
PreparedStatement ps = con.prepareStatement(sql);
ps.setInt(1, runs);     // IN p_runs
ps.setInt(2, matches);  // IN p_matches
ResultSet rs = ps.executeQuery();
```

The three UDFs in this project:

| Function | Parameters | Returns |
|----------|-----------|---------|
| `fn_batting_average(runs, matches)` | INT, INT | DECIMAL — runs ÷ matches |
| `fn_player_grade(runs, wickets, role)` | INT, INT, VARCHAR | VARCHAR — Elite/Good/Average/Developing |
| `fn_format_player_label(name, role, team)` | VARCHAR × 3 | VARCHAR — "Name (Role) — Team" |

The `/api/functions/all-players` endpoint applies all three to every cricketer in one query:

```sql
SELECT cr.name, cr.role, t.name AS team_name,
       fn_batting_average(COALESCE(cr.runs,0), GREATEST(COALESCE(cr.matches,1),1)) AS batting_average,
       fn_player_grade(COALESCE(cr.runs,0), COALESCE(cr.wickets,0), cr.role)       AS player_grade,
       fn_format_player_label(cr.name, cr.role, t.name)                             AS player_label
FROM cricketers cr JOIN teams t ON t.id = cr.team_id
ORDER BY cr.name
```

This runs a single query and returns computed columns alongside raw data — no need to call each function separately.

## 16. Common Mistakes and Fixes {#common-mistakes-and-fixes}

### Maven Assembly Plugin (wrong) vs Shade Plugin (right)

```
Error: java.lang.ClassNotFoundException: org.apache.catalina.startup.Tomcat
```

**Cause:** `maven-assembly-plugin` overwrites duplicate `META-INF/services` files.  
**Fix:** Use `maven-shade-plugin` with `ServicesResourceTransformer`.

### SQL Collation Error `[1267]`

```
SQL Error [1267] [HY000]: Illegal mix of collations
(utf8mb4_unicode_ci,IMPLICIT) and (utf8mb4_0900_ai_ci,IMPLICIT)
```

**Cause:** JDBC connection collation (`utf8mb4_0900_ai_ci` default) mismatches table columns (`utf8mb4_unicode_ci`).  
**Fix:** Add `&connectionCollation=utf8mb4_unicode_ci` to the JDBC URL.

### Tomcat Says "Port already in use"

```
java.net.BindException: Address already in use
```

**Fix:** Kill the previous process:
```bash
kill $(lsof -ti:8080)
# or
fuser -k 8080/tcp
```

### `doOptions` Not Overridden — CORS Preflight Fails

Browsers send OPTIONS before PUT/POST/DELETE. Without `doOptions()` returning 204 with CORS headers, the preflight fails and the actual request is never sent.  
**Fix:** `BaseServlet.doOptions()` handles this for all servlets automatically.

### Gson Cannot Deserialise JSON Field Names with Underscores

Gson maps `{"world_cups_won": 5}` to a field called `worldCupsWon` if the POJO uses camelCase but the JSON uses snake_case.  
**Fix:** Use `@SerializedName("world_cups_won")` on the field, or configure Gson with `setFieldNamingPolicy(FieldNamingPolicy.LOWER_CASE_WITH_UNDERSCORES)`.

In this project the models use camelCase and the JSON sent by the React frontend should also use camelCase — Gson handles this automatically.
