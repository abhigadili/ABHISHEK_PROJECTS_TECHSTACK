# Security

## 1. Layers
```
Client ─TLS (terminate in front of the gateway)─► Gateway: CORS, rate limit, JWT signature/expiry + Redis revocation, path-role rules
        └► Service: JwtAuthenticationFilter (again) → @PreAuthorize (role / permission) → ownership checks (@employeeAccess, @authz) → data
```
Implemented in `common-library/.../security/*`, `api-gateway/.../GatewaySecurityConfig.java`, `auth-service`.

## 2. Authentication
* `POST /api/v1/auth/login` - BCrypt (cost 10) password check, lockout after 5 failed attempts within 15 min (Redis counter, 15 min lock), response `accessToken` (30 min), `refreshToken` (rotating, stored only as a SHA-256 hash), `mustChangePassword`.
* **JWT (HS256)** signed by `NimbusJwtEncoder` with `JWT_SECRET`. Claims: `sub` (username), `uid`, `eid` (employee id), `email`, `roles`, `perms`, `mcp` (must-change-password), `jti`, `iat`, `exp`.
* **Revocation:** logout / password change / account disable / exit put the `jti` into Redis (`hr:auth:revoked:<jti>`) for its remaining life. Services and the gateway check it on every request.
* **Must-change-password:** the user-context interceptor blocks every endpoint except change-password while `mcp=true` (bootstrap admin, admin-created and reset accounts).
* Password rules (`@StrongPassword`): 10-72 characters with upper, lower, digit and symbol, no whitespace; reset tokens are random 256-bit values, single use, 30 min.

## 3. Authorisation
Roles: `EMPLOYEE`, `MANAGER`, `HR_ADMIN`, `PAYROLL_ADMIN`, `FINANCE_ADMIN`, `PROJECT_MANAGER`, `SUPER_ADMIN` (SUPER_ADMIN passes every role check). Permissions (seeded in auth `V3`) are finer grained and travel in the token as `perms`.

| Capability | Roles / permission |
|---|---|
| Own profile, leave, attendance, timesheet, payslips, tax declaration, resignation, documents | any authenticated user (own data only) |
| Approve team leave / timesheets / corrections / reviews, see team data | MANAGER of that employee (resolved via the org chart), HR_ADMIN |
| Employee master data, leave policy, holidays, documents verification, exit steps, performance cycles | HR_ADMIN (`PERM_EMPLOYEE_*`, `PERM_LEAVE_APPROVE`, ...) |
| Salary structures, payroll runs, loans, adjustments | PAYROLL_ADMIN (`PERM_PAYROLL_PROCESS`); approval of a run by a second person |
| Tax rules, declaration review | FINANCE_ADMIN (`PERM_TAX_REVIEW`) |
| Customers, projects, allocations | PROJECT_MANAGER |
| Users, roles, permissions, audit history, Kafka info, email settings | SUPER_ADMIN (some HR_ADMIN) |

```java
@PreAuthorize("hasAnyRole('HR_ADMIN','SUPER_ADMIN') or hasAuthority('PERM_LEAVE_APPROVE')")
@PreAuthorize("@authz.isSelfOrHr(#employeeId)")                   // AuthorizationService (bean name `authz`)
@PreAuthorize("hasAuthority('PERM_PAYROLL_PROCESS')")            // 9 endpoints; 39 endpoints use the HR_ADMIN / SUPER_ADMIN role rule
// EmployeeAccess (bean `employeeAccess`).canView(employeeId, managerId): self, direct manager chain or HR
```
Gateway rules (`GatewaySecurityConfig`): public = login, refresh, forgot / reset password, `/ping`, swagger; everything else authenticated; admin-only areas (e.g. `/api/v1/auth/users/**`, `/api/v1/payroll/runs/**`) additionally require the role at the edge.

## 4. Data protection
* PAN, bank account, customer tax number: AES-256-GCM column encryption (`EncryptedStringConverter`, key from `HR_DATA_ENCRYPTION_KEY`, random IV per value); masked in responses and in audit payloads (`LogMasker`).
* Money topics are redacted in `event_history`.
* `audit_history` is append-only: MySQL triggers (`trg_audit_history_no_update` / `_no_delete`) reject UPDATE/DELETE, and the runtime DB user has no DDL rights.
* Uploads: extension allow-list, **content sniffing** (`FileTypeSniffer`) so a renamed file is rejected, size limit, stored under generated names outside the web root, category access policy, every download logged.
* Error bodies never include stack traces or SQL (`server.error.include-*: never`); `GlobalExceptionHandler` maps to `ApiError` with a correlation id.
* `RequestHeaderValidationFilter` rejects path-traversal / NUL-byte URLs, headers over 8 KB and malformed correlation ids before any controller runs; `max-http-form-post-size` is 2 MB.

## 5. Secrets and configuration
No credential is in source. `.env` (git-ignored) feeds Compose and `scripts/`; `.env.example` has placeholders. Separate DB users: **migration** (Flyway only) and **hr_app** (DML + EXECUTE). The bootstrap SUPER_ADMIN is created at first start from `HR_BOOTSTRAP_ADMIN_*` and must change the password at first login.

## 6. Known limits / hardening backlog
HS256 shared secret → move to RS256/JWKS; TLS and Redis/Kafka authentication are infrastructure tasks; add MFA and e-mail verification for password reset; Docker images currently run as root inside the container (add a `USER` line) and are not scanned.
