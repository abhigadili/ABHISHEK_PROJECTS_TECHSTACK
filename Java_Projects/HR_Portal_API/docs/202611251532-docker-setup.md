# Docker Setup

Three ways to run, from lightest to heaviest. **Verification status:** `docker compose config` (all profiles) validates; the infrastructure containers (Kafka, Kafka UI, Redis) run and are what the local services use; the gateway image was built successfully with the shipped `Dockerfile`. The fully containerised `--profile apps` stack (all 16 images + containerised MySQL) was **not** started end to end in this environment - the local run uses jars started by `scripts/start-all.sh`.

## 1. What is in `docker-compose.yml`
| Service | Profile | Image / build | Host port | Notes |
|---|---|---|---|---|
| `kafka` | default | `apache/kafka:3.9.0` (KRaft, single node) | 9192 (→ container 9092) | internal listener `kafka:29092`, advertised external `localhost:9192`; volume `hr-kafka-data` |
| `kafka-init` | default | same image | - | runs `infrastructure/kafka/create-topics.sh` (24 topics + `.DLT`, 3 partitions) after Kafka is healthy, then exits |
| `kafka-ui` | default | `provectuslabs/kafka-ui` | 9190 | browse topics / messages / consumer groups |
| `redis` | default | `redis:7-alpine` | 9379 (→ 6379) | `infrastructure/redis/redis.conf` (AOF on, 256 MB, `allkeys-lru`); optional `REDIS_PASSWORD`; volume `hr-redis-data` |
| `mysql` | `mysql` | `mysql:8.0` | 3317 (→ 3306) | only for machines without MySQL; creates the 15 databases and the `MYSQL_APP_USER` with DML + EXECUTE; `--log-bin-trust-function-creators=1`, 300 connections; volume `hr-mysql-data` |
| `api-gateway` + 15 services | `apps` | built from `<module>/Dockerfile` | 9080, 9101-9115 | env from the shared `x-app-env` block; services depend on `kafka-init` (completed), `redis` (healthy) and `mysql` (if that profile is on); share volume `hr-storage` (`/data/storage`) |

Network: one default Compose network; services reach each other by service name (`http://employee-service:9102`) - the `*_SERVICE_URL` variables in `x-app-env` override the `localhost` defaults of `application.yml`.

## 2. Mode A - local services, Docker for infrastructure only (default, used for development)
Uses the **existing MySQL server on the host**; no MySQL container.
```bash
cp .env.example .env && $EDITOR .env           # placeholders only in the example; real values stay in .env (git-ignored)
docker compose up -d                           # kafka, kafka-init, kafka-ui, redis
docker compose ps                              # kafka + redis (healthy), kafka-init (exited 0)
./scripts/create-databases.sh                  # 15 DBs + hr_app user on the host MySQL (uses the privileged `MYSQL_MIGRATION_*` login from `.env`)
./scripts/build.sh                             # mvn clean package
./scripts/start-all.sh                         # 15 services + gateway, waits for /ping
./scripts/stop-all.sh                          # stops them by recorded pid (does not touch Docker)
docker compose down                            # stop infra (volumes kept)   |  down -v  also deletes Kafka/Redis data
```
*Expected output of `start-all.sh`:* `hr-auth-service starting on :9101` ... then `hr-auth-service UP` for each, finally `hr-api-gateway UP`. Logs: `logs/<service>.out` / `.log`.

## 3. Mode B - everything in containers
```bash
./scripts/build.sh                                                   # jars must exist: the Dockerfiles COPY target/<jar>
docker compose --profile mysql --profile apps up -d --build          # MySQL container + all 16 images
curl localhost:9080/ping
```
Each Dockerfile (identical shape):
```dockerfile
FROM eclipse-temurin:21-jre
WORKDIR /app
COPY target/hr-employee-service.jar app.jar
EXPOSE 9102
ENV JAVA_OPTS="-XX:MaxRAMPercentage=70 -XX:+UseSerialGC"
HEALTHCHECK --interval=15s --timeout=3s --start-period=90s --retries=6 CMD bash -c ':> /dev/tcp/127.0.0.1/9102' || exit 1
ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar"]
```
Healthcheck = TCP connect to the service port (no HTTP client needed in the image). Memory: ~300-450 MB per JVM; the whole stack needs roughly 6-8 GB RAM - lower `JAVA_OPTS` (`-Xmx256m`) on small machines.

### Using the host's MySQL from containers (Mode B without the `mysql` profile)
The compose default for `MYSQL_HOST` is the container name `mysql`. To use the host MySQL set in `.env`: `DOCKER_MYSQL_HOST=<address reachable from containers>` (on Linux the docker bridge gateway, typically `172.17.0.1`, **not** `localhost`/`host.docker.internal`, which is not defined on Linux by default), `DOCKER_MYSQL_PORT`, `DOCKER_MYSQL_MIGRATION_USER` / `_PASSWORD`; MySQL must listen on that interface (`bind-address`) and the app user's host must allow it: `scripts/create-databases.sh` creates the user for `HR_DB_USER_HOST` (default `localhost`, so set it to `%` or the container subnet for Mode B); the container's own init script uses `%`.

## 4. Environment variables
See `README.md` (Configuration). In Compose they come from `.env` through `${VAR}` interpolation; **nothing secret is written into the compose file or Dockerfiles**. `MYSQL_ROOT_PASSWORD`, `JWT_SECRET`, `HR_DATA_ENCRYPTION_KEY`, `MYSQL_APP_*` have no defaults - Compose fails with an "empty variable" warning if you forget them.

## 5. Volumes and data
| Volume | Content | Reset |
|---|---|---|
| `hr-kafka-data` | topics, offsets | `docker compose down -v` (loses events / consumer positions; read models are rebuilt only from new events) |
| `hr-redis-data` | caches, sessions, refresh tokens, revoked ids | safe to delete (users log in again) |
| `hr-mysql-data` | the 15 databases (profile `mysql`) | destroys all HR data |
| `hr-storage` | payslip PDFs and uploaded documents - **shared** by payroll and document services | back up with the database |

## 6. Operations cheat-sheet
```bash
docker compose logs -f kafka | redis | auth-service          # container logs
docker exec -it hr-redis redis-cli [-a "$REDIS_PASSWORD"]      # inspect keys (redis-guide)
docker exec hr-kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server kafka:29092 --list    # kafka/202611251532-local-commands.md
docker compose --profile mysql --profile apps config -q        # validate the compose file
docker compose up -d --build employee-service                  # rebuild one service after build.sh
```

## 7. Troubleshooting
| Symptom | Cause / fix |
|---|---|
| Service exits with "Access denied" for the migration user | the migration login needs DDL, TRIGGER, CREATE ROUTINE (and SUPER/`log_bin_trust_function_creators` when the binary log is on) |
| `Failed to connect to localhost:9192` from a container | containers must use `kafka:29092`; `localhost:9192` is for processes on the host |
| Services start before topics exist | they `depends_on` `kafka-init` (completed); topics also exist as `NewTopic` beans |
| Port already in use | change the host side of the mapping (`KAFKA_HOST_PORT`, `REDIS_HOST_PORT`, `DOCKER_MYSQL_HOST_PORT`) |
| Flyway "failed migration" after a crashed first start (development) | `HR_FLYWAY_REPAIR=true` once; or `HR_FLYWAY_RESET=true` with `SPRING_FLYWAY_CLEAN_DISABLED=false` to rebuild that service's own database (destroys its data). Never on production |

## 8. Production notes
Pin image versions (Kafka UI uses `latest` here for convenience), run as a non-root user (add `USER` to the Dockerfiles), use a multi-broker Kafka and an authenticated Redis, put TLS in front of the gateway, store secrets in a secret manager instead of `.env`, and size connection pools: each service uses 4 Hikari connections, so 15 services need ≥ 60 MySQL connections plus headroom.
