# Kafka topics

24 business topics, each with **3 partitions** and a dead-letter twin `<topic>.DLT` (3 partitions). Replication factor 1 (single dev broker). Created by `infrastructure/kafka/create-topics.sh` (compose `kafka-init`) and, as a fallback, declared as `NewTopic` beans in `KafkaCommonConfig`. Message key = employee id (or subject id), so all events of one employee stay ordered within a partition. Value = JSON of the record in `HrEvents` (`common-library/.../events/HrEvents.java`).

| # | Topic | Producer service(s) | Consumer service(s) | Purpose |
|---|---|---|---|---|
| 1 | `employee.created` | employee-service | attendance-service, auth-service, leave-service, notification-service, organization-service, performance-service, reporting-service, tax-service, timesheet-service | new hire onboarded: provisions login, org chart node, leave/attendance/tax/timesheet/performance read models, welcome notice |
| 2 | `employee.updated` | employee-service | attendance-service, leave-service, notification-service, organization-service, performance-service, reporting-service, tax-service, timesheet-service | profile / org change: keeps read models and reports in sync |
| 3 | `employee.terminated` | employee-service | attendance-service, auth-service, leave-service, notification-service, organization-service, performance-service, project-service, reporting-service, tax-service, timesheet-service | employee terminated/inactivated: disables login, frees allocations |
| 4 | `leave.applied` | leave-service | notification-service, reporting-service | leave request raised (history, reporting) |
| 5 | `leave.approved` | leave-service | attendance-service, notification-service, reporting-service | approved leave: attendance marks the days as on-leave |
| 6 | `leave.rejected` | leave-service | notification-service, reporting-service | rejected request (history, reporting) |
| 7 | `leave.cancelled` | leave-service | attendance-service, notification-service, reporting-service | cancelled leave: attendance releases the days |
| 8 | `attendance.checked-in` | attendance-service | notification-service, reporting-service | check-in fact |
| 9 | `attendance.checked-out` | attendance-service | notification-service, reporting-service | check-out fact with worked / overtime minutes |
| 10 | `attendance.corrected` | attendance-service | notification-service, reporting-service | approved attendance correction |
| 11 | `payroll.processed` | payroll-service | notification-service, reporting-service | payroll run finished: totals per department for reports |
| 12 | `payslip.generated` | payroll-service | document-service, notification-service | payslip PDF produced: document service registers it |
| 13 | `tax.declaration.submitted` | tax-service | notification-service, reporting-service | declaration submitted for review |
| 14 | `tax.declaration.reviewed` | tax-service | notification-service, reporting-service | declaration approved / rejected |
| 15 | `performance.review.submitted` | performance-service | notification-service, reporting-service | review stage submitted |
| 16 | `performance.review.approved` | performance-service | notification-service, reporting-service | final rating approved |
| 17 | `timesheet.submitted` | timesheet-service | notification-service, reporting-service | week submitted for approval |
| 18 | `timesheet.approved` | timesheet-service | notification-service, reporting-service | week approved |
| 19 | `resignation.submitted` | exit-service | employee-service, notification-service, reporting-service | resignation raised: employee status moves to ON_NOTICE |
| 20 | `employee.exited` | exit-service | attendance-service, auth-service, employee-service, leave-service, notification-service, organization-service, performance-service, project-service, reporting-service, tax-service, timesheet-service | last working day completed: login revoked, allocations closed, status RESIGNED or TERMINATED |
| 21 | `settlement.processed` | exit-service | notification-service, payroll-service | final settlement paid: payroll records it |
| 22 | `holiday.changed` | holiday-service | attendance-service, notification-service | holiday added / changed / removed: attendance refreshes its snapshot |
| 23 | `project.allocation.changed` | project-service | notification-service, reporting-service | allocation added / changed / ended |
| 24 | `notification.requested` | attendance-service, auth-service, document-service, exit-service, leave-service, payroll-service, performance-service, project-service, tax-service, timesheet-service | notification-service | command: send in-app + e-mail notification (templated) |

All topics are additionally consumed by `hr-notification-service` into `event_history` (audit trail of what happened; payload of money topics redacted). Consumer group id = service name (e.g. `hr-notification-service`), so each service receives every message once.
