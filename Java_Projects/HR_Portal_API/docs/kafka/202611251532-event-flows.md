# Event flows

## 1. Onboarding
```
employee-service ──employee.created──► auth-service          create login (username emp00001) + notification.requested ACCOUNT_PROVISIONED
                                    ├► organization-service  org_employee_nodes (org chart)
                                    ├► leave / attendance / tax / timesheet / performance   local employee read model
                                    ├► reporting-service     rpt_employees
                                    └► notification-service  welcome in-app + e-mail, event_history
```

## 2. Leave
```
leave-service ─leave.applied──► notification (manager) , reporting
              ─leave.approved─► attendance-service (approved_leave_days → day shows ON_LEAVE, no absent flag)
                              ├► notification (employee) , reporting
              ─leave.cancelled► attendance-service (release days)
```

## 3. Payroll
```
payroll-service ─payroll.processed─► reporting (cost per department), notification history
                ─payslip.generated─► document-service (registers PDF under category PAYSLIP) ─notification.requested─► employee
```

## 4. Exit
```
exit-service ─resignation.submitted─► employee-service (status ON_NOTICE), reporting, notification (manager + HR)
             ─employee.exited──────► employee-service (RESIGNED or TERMINATED by exit type), auth-service (disable login, revoke sessions),
                                     project-service (end allocations), organization (node inactive), leave/tax/timesheet/performance read models
             ─settlement.processed─► payroll-service (marks settlement paid), notification
```

## 5. Attendance and holidays
```
attendance-service ─attendance.checked-in/out/corrected─► reporting (facts), notification history
holiday-service ─holiday.changed─► attendance-service (refresh holiday_snapshots → no absent on holidays)
```

## 6. Notification command
Any service → `notification.requested` → notification-service: Redis `SETNX` on `dedupKey` (duplicates dropped) → render template → insert in-app row → queue e-mail (bounded `EmailDispatchQueue`, LOG or SMTP). Failures: retry topics (1 s, 2 s) then `notification.requested-dlt`.

## Reliability path of every publish
```
service transaction:  business rows + outbox_events row  ──commit──►  afterCommit: send to Kafka, stamp sent_at
                                                       └─ if the broker is down: OutboxRelay (every 10 s) re-sends rows with sent_at IS NULL
consumer:  IdempotentEventProcessor.process(eventId, consumer, work)   (ledger insert + work in ONE transaction → duplicates skipped)
failure :  DefaultErrorHandler: exponential back-off 0.5 s ×2 for ≤ 5 s → <topic>.DLT   (IllegalArgumentException = not retryable)
```
