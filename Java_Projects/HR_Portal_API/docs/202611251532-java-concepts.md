# Java Concepts Used in This Project

Java 21 (LTS). Each concept: **what / why / where / HR use / example / expected output / pros & cons**. Paths relative to the project root; `<svc>` = a service module. Companion guides cover collections, streams, concurrency in depth.

## 1. Records (immutable data carriers)
* **What:** `record R(A a, B b)` - final fields, constructor, accessors, `equals/hashCode/toString` generated. **Why:** DTOs and events are pure data; immutability makes them thread-safe and safe to cache / put on Kafka. **Where:** 348 records - request/response DTOs (`<svc>/.../dto/*Dtos.java`), events (`common-library/.../events/HrEvents.java`), engine values (`payroll-service/.../engine/PayrollModel.java`), queue items (`PunchImportQueue.Punch`, `DelayQueue` `Task`).
```java
public record LoginRequest(@NotBlank @Size(max = 150) String username, @NotBlank @Size(max = 200) String password) { }
public record PayrollLine(String employeeId, String departmentId, BigDecimal gross, BigDecimal deductions, BigDecimal net) { }
```
*Output:* `new PayrollLine("e1","d1",38095.20,38095.20,0.00)` → JSON `{"employeeId":"e1",...,"net":0.00}` via Jackson. **Pros:** concise, immutable, validation annotations work on components. **Cons:** no inheritance; mutable state needs a class (entities stay classes).

## 2. Enums with behaviour and `EnumMap` / `EnumSet`
`employee-service/.../entity/Enums.java`: `EmployeeStatus { ACTIVE, INACTIVE, ON_NOTICE, RESIGNED, TERMINATED; boolean isLeft() }`. All statuses in the system (leave, payroll run, resignation ...) are enums stored as strings (`@Enumerated(STRING)`, 61 places) so reordering never corrupts data. Strategy keyed by enum: `EnumMap<CalcType, ComponentCalculator>` (`SalaryCalculationEngine`).
`EmployeeStatus.RESIGNED.isLeft()` → `true`. **Pros:** type-safe closed sets, switch-friendly. **Cons:** adding a value needs a code deploy (and sometimes a DB CHECK change).

## 3. Switch expressions
```java
return switch (status) {                                     // FeignGlobalConfig.hrErrorDecoder
    case NOT_FOUND -> new ResourceNotFoundException(message);
    case BAD_REQUEST, UNPROCESSABLE_ENTITY -> new BadRequestException(message);
    case CONFLICT -> new ConflictException(message);
    default -> status.is4xxClientError() ? new DownstreamClientException(status, message) : retryOrUnavailable(response, methodKey);
};
```
`ExitTaskService` uses `yield` blocks to build the right task subclass per kind. *Output:* downstream 409 → local `ConflictException` → HTTP 409. **Pros:** expression (no fall-through), exhaustive for enums. **Cons:** `default` can hide a newly added enum value.

## 4. Pattern matching for `instanceof`
`AsyncReportService`: `if (je instanceof JoiningExitSummary j && hc instanceof HeadcountReport h && h.active() > 0) { ... j.totalLeavers() ... }` - test, cast and bind in one step (17 uses).

## 5. Text blocks
`"""` multi-line SQL in `OrgHierarchyJdbc` (recursive CTEs) and `LeaveCalendarService` - readable, no `+` concatenation (which would also invite injection mistakes).

## 6. Generics and bounded types
`CrudService<E extends BaseEntity, Q, R>` (`common-library/.../persistence/CrudService.java`): one implementation of list / get / create / update / soft-delete for any entity, request record and response record (subclasses: `TaskService`, catalog services).
`<T> Mono<T> get(String uri, Class<T> type, Object... vars)` in `HrWebClient`; `BeanMapper.toRecord(Object, Class<T>)`; `PageResponse<T>`.
**HR use:** a new master-data screen = one tiny subclass. **Pros:** reuse with type safety. **Cons:** erased types need `Class<T>` tokens / `ParameterizedTypeReference` for collections.

## 7. Interfaces, default methods, strategy / polymorphism
```java
public interface HrEvent { EventMetadata metadata(); String employeeId(); default String eventId() { return metadata().eventId(); } }
public interface ComponentCalculator { CalcType supports(); BigDecimal calculate(StructureItem item, Context ctx); }   // 8 implementations
public interface DateRangeAware { LocalDate rangeStart(); LocalDate rangeEnd(); }      // lets one validator serve many DTOs
```
Abstract classes: `BaseEntity`, `SoftDeletableEntity`, `ExitTask` (JPA inheritance), `CrudService`, `ApiException`. **Pros:** open/closed, testable. **Cons:** indirection.

## 8. Lambdas, functional interfaces, method references
`Supplier` (`section(name, () -> ...)`, `DistributedLockService.withLock(name, ttl, Supplier<T>)`), `Function`, `Consumer` (`IdempotentEventProcessor.handle(..., Consumer<T> handler)`), `Comparator.comparing(...).reversed().thenComparing(...)`, `TransactionTemplate.execute(status -> ...)`, `CompletableFuture.supplyAsync(() -> ...)`, `Retryer`/`RequestInterceptor` as lambdas in `FeignGlobalConfig`.
```java
idempotent.handle(payload, EmployeeCreated.class, "auth.employee-created", e -> users.provisionForEmployee(e.employeeId(), ...));
```
**Pros:** behaviour as a parameter (template-method without subclassing). **Cons:** deep lambda nesting hurts stack traces.

## 9. `Optional`
55 uses at API boundaries (`findBy...` returns `Optional<T>`; `getOptional` in `HrWebClient` returns `Mono<Optional<T>>`). Pattern: `repo.findById(id).orElseThrow(() -> ResourceNotFoundException.of("Employee", id))` → 404. Never used as a field or parameter.

## 10. Exceptions
Checked exceptions are confined to I/O boundaries (JDBC `SQLException` in `AttendanceJdbc`, crypto, JSON) and translated at the boundary to unchecked business exceptions (`ServiceUnavailableException`, `IllegalStateException`). Hierarchy: `ApiException` → specific exceptions → `GlobalExceptionHandler` (see `logging-exception-handling`). **try-with-resources** for every `Connection`, `CallableStatement`, `ResultSet`, `AdminClient`, `KafkaConsumer`.

## 11. `BigDecimal`, `java.time`, UUIDs - correctness basics
* Money, rates, hours: `BigDecimal` (530 uses) with explicit `RoundingMode.HALF_UP` and scale (`decimal(15,2)` in MySQL) - never `double`. Compare with `compareTo`, not `equals`.
* Dates: `LocalDate` (business dates), `Instant` (timestamps, always UTC), `YearMonth` (payroll month keys); `hibernate.jdbc.time_zone: UTC`; the attendance zone is configurable (`hr.attendance.zone`).
* Ids: `UUID.randomUUID()` / Hibernate `@UuidGenerator`, validated by `@ValidEmployeeId`.
*Output:* `new BigDecimal("0.1").add(new BigDecimal("0.2"))` → `0.3` (exactly), unlike `0.1 + 0.2 = 0.30000000000000004`.

## 12. Annotations and reflection
Custom annotations: `@ValidDateRange`, `@StrongPassword`, `@NoLeaveOverlap`, ... (8 `@interface`s) with `ConstraintValidator`s. Reflection: `BeanMapper` (record components → entity fields, cached in a `ConcurrentHashMap`), `FieldDiff` in employee-service (compare two objects field by field for the change log).
**Pros:** declarative rules, generic mapping. **Cons:** reflection is slower and fails at runtime, not compile time.

## 13. Inner / nested classes, access control, immutability
`HrWebClient.Bound` (inner class capturing the outer client and an explicit token), nested validators inside annotations, nested `@Service` classes in `LeaveCatalogService`, `private static final` constants, `final` fields everywhere, `Collections.unmodifiableList`, `List.copyOf`. Utility classes are `final` with private constructors (`BeanMapper`, `PageRequests`, `LogMasker`, `AllocationCalculator`).

## 14. Concurrency, collections, streams
See `java-concurrency-guide`, `java-collections-guide`, `java-streams-guide`. `volatile` for safely published shared state (`CryptoKeyHolder.key`), daemon worker threads with `@PreDestroy` shutdown.

## 15. Security-relevant Java APIs
`SecureRandom` (reset tokens, IVs, passwords - 8 uses), `MessageDigest` SHA-256 (refresh-token hashes, AES key derivation), `Cipher` `AES/GCM/NoPadding` with a random 12-byte IV prepended and Base64 output (`CryptoKeyHolder`), BCrypt via Spring Security.
```java
Cipher c = Cipher.getInstance("AES/GCM/NoPadding");
c.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(128, iv));      // iv: 12 random bytes, stored with the ciphertext
```
*Output:* the same bank account number encrypted twice gives two different Base64 strings (random IV); both decrypt to the original; tampering fails with `Decryption failed` (GCM authenticates).

## 16. Java 21 features deliberately **not** used
Virtual threads, sealed hierarchies, record patterns in `switch` - the project targets conservative, library-friendly constructs (JPA entities cannot be records; Hibernate and Spring proxies need non-final classes). Virtual threads (`spring.threads.virtual.enabled=true`) are a straightforward later optimisation for the blocking Feign / JDBC paths.

## Pros / cons overall
| Pros | Cons |
|---|---|
| Modern concise Java (records, switch expressions, text blocks) keeps DTOs and rules short and immutable | Mixed paradigms (blocking Feign, reactive WebClient, CompletableFuture) require discipline on threads and context |
| Strong typing + generics remove casts; BigDecimal / java.time give exact money and date math | Reflection-based mapping and proxies trade compile-time safety for brevity |
